# Витрина `/` — спека

Макет: канвас «Маркетплейс», артборд `Main.dc.html` (шапка уже сделана: `shared/ui/site-header`).
Цель страницы — потренировать **SSG / ISR / SSR** и понять, как они ломаются друг об друга.

## Что нужно сделать

Всё под шапкой: hero-слайдер + два промо-блока, сетка «Категории», две полки товаров («Хиты продаж», «Вам может понравиться»).

### 1. Данные (`features/storefront`)

- [ ] Категории корневого уровня: напишите запрос сами. Фича не может импортировать другую фичу (boundaries) — решите, где он живёт: `shared`, отдельная фича или сборка в `app/`.
- [ ] Запрос «Хиты продаж»: топ-6 по `popularity` (по всему каталогу или по одному на категорию — выберите и запишите почему).
- [ ] Запрос «Вам может понравиться»: пока без персонализации — другой срез (например, по `rating` с `reviewsCount > N`). Настоящая персонализация — отдельный шаг.
- [ ] Hero и промо: в БД таблицы нет. Варианты: константа в коде / таблица `banners` + сид. Подумайте, что из этого должно менять редактор без деплоя.
- [ ] Карточка товара — **как в макете** (3:4 на витрине, 1:1 в каталоге).

### 2. Рендеринг: решить и обосновать по каждому блоку

| Блок                                        | От чего зависит                     | Ваш выбор (SSG / ISR / SSR / клиент) | Почему |
| ------------------------------------------- | ----------------------------------- | ------------------------------------ | ------ |
| Hero + промо                                | редактор, редко                     |                                      |        |
| Категории (сетка и меню в шапке)            | дерево категорий, почти не меняется |                                      |        |
| Хиты продаж                                 | `popularity` общий для всех         |                                      |        |
| Вам может понравиться                       | пока общий срез                     |                                      |        |
| Счётчики в шапке (заказы/избранное/корзина) | **конкретный пользователь**         |                                      |        |

Ориентир: страница `/` целиком — **ISR**. Всё, что зависит от пользователя, выносится из серверного HTML.

### 3. Грабли, которые стоит пройти руками

1. **`cookies()` / `headers()` в root layout или в шапке делает ВСЕ страницы динамическими.** Счётчики в шапке должны либо приходить с клиента (fetch после гидрации), либо рендериться в `<Suspense>`. Проверьте по выводу `next build`: `○` static, `●` SSG/ISR, `ƒ` dynamic.
2. **Сборка ходит в БД.** SSG/ISR на этапе `next build` читает Neon — `DATABASE_URL` должен быть доступен в Build env на Vercel (Production и Preview). У нас одна БД на всё — осторожно с сидом во время деплоя.
3. **Кэш запросов к БД.** `fetch`-кэша нет — Drizzle не ходит через `fetch`. Выясните по документации Next 16.4, что здесь актуально: `export const revalidate`, `unstable_cache`, `'use cache'`. Мы **сознательно отключили `cacheComponents`** в `next.config.ts` — если решите включать, это отдельное решение, запишите в документацию архитектуры.
4. **Теги и ручная инвалидация.** Придумайте теги (`categories`, `products:hot`), сделайте route handler/Server Action с `revalidateTag`, проверьте, что после смены цены/сида витрина обновляется без редеплоя.
5. **Размеры картинок.** `next/image` с `fill` требует `sizes`, иначе грузится лишнее. Первый экран — `priority`.
6. **Стили.** Токены цветов в макете — `--text-tertiary`, `--border-default`, `--bg-container`, `--bg-brand`, `--bg-neutral`, `--text-on-brand` и т.д. Проверьте, что они реально определены в стилях drill-kit, а не молча падают.

### 4. Интерактив (клиентские острова)

- Слайдер hero (точки-индикаторы) — клиентский компонент, а не весь блок.
- Стрелки ‹ › на полках — прокрутка/пагинация; на сервере должен остаться полный HTML карточек.
- «В корзину» / «В избранное» — пока можно заглушки, логика в шаге про корзину.

## Критерии готовности

- [ ] `npm run build` показывает `/` как `●` (ISR) с вашим `revalidate`, а не `ƒ`.
- [ ] В выключенном JS страница читаема: видны категории и обе полки с товарами.
- [ ] Смена `popularity` у товара в БД + `revalidateTag` → витрина обновилась без деплоя.
- [ ] Счётчики в шапке не делают страницу динамической.
- [ ] `npm run lint`, `npm run typecheck` проходят; слои не нарушены (feature → только shared).
- [ ] В таблице выше заполнены все пять строк с обоснованием.

- Каталог (`features/catalog`, `app/catalog`) и карточка товара удалены — будут пересобраны по макету `Catalog.dc.html` отдельным шагом. Карточка на витрине и в каталоге должна быть одной и той же (3:4 / 1:1).

- Запросов к БД в приложении сейчас нет: `getRootCategories` и т.п. нужно написать заново (в `features/…` или `shared`, см. раздел «Данные»).
